# AI Service

Поддерживает локальную проекцию результатов Screening и материалов Content,
векторный индекс по чанкам текста и историю генераций (пояснений) —
не является источником истины ни для результата, ни для публикаций, ни для
прав доступа (см. [`ARCHITECTURE.md`](../../ARCHITECTURE.md), раздел «AI:
события → проекция → проверенный контекст»). Данные — в собственной базе
`ai`. HTTP/WSS-API пока не реализован — этот пакет отвечает только за
схему, миграции и их проверку (см. `services/iam/README.md` для общей
структуры пакета).

Этого каталога не было в репозитории до выполнения задачи — создан с нуля.

## Таблицы

| Таблица | Назначение |
| --- | --- |
| `result_projection` | Локальная (возможно отстающая) копия результата Screening на пару (`result_id`, `version`); обновляется событиями, не является источником истины. |
| `article_projection` | Локальная копия опубликованной версии материала Content на пару (`article_id`, `version`). |
| `article_chunks` | Фрагменты текста конкретной версии материала для поиска; `UNIQUE(article_id, version, chunk_index)`. |
| `chunk_embeddings` | Эмбеддинг чанка. Хранится как `double precision[]`, а не тип `vector` (pgvector) — чтобы не тащить лишнее расширение Postgres без явного запроса; переход на pgvector — осознанный будущий шаг, если понадобится реальный similarity search. |
| `generations` | Одна попытка генерации пояснения для `(result_id, result_version)` из `result_projection` — FK гарантирует, что генерация не создаётся раньше проекции результата. `owner_subject_id` — субъект IAM, без FK. |
| `generation_sources` | Какие чанки использованы как источник для генерации (цитирование). |
| `outbox_events`, `inbox_messages` | Локальные outbox/inbox, см. `packages/db`. |

## MIS-23

Миграция `0002_mis23_access_model`: `generations.subject_id` переименован в
`owner_subject_id` — «operationId/задания/WSS имеют owner_subject_id».
`result_projection.subject_id` не переименован: это копия поля Screening
(проекция), а не владелец операции.

## Откуда взяты колонки

Для AI таблица задачи не даёт отдельных гарантий (только список таблиц),
поэтому состав полей — наиболее спекулятивная часть всей работы: выведен из
`ARCHITECTURE.md` (раздел 8) и общей логики проекций/векторного поиска, без
опоры на protobuf-контракт (для AI он не описан в `contracts/`). Исходный
ERD (Plane) недоступен из среды разработки инструмента, которым готовилась
эта миграция. **Эту схему нужно сверить на ревью внимательнее остальных.**

## Запуск

Из корня репозитория: `make up`, затем `make test-ai`
(или `cd services/ai && uv sync && uv run pytest -q`).
